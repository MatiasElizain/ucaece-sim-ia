Simulador de Arquitectura DeepSeek

Contexto

DeepSeek-V3 es un modelo de lenguaje de tipo Mixture of Experts (MoE) con 671 B de parámetros totales, de los cuales solo 37 B se activan por token. Incorpora innovaciones clave: la atención con clave-valor latente (MLA) y el enrutamiento eficiente de expertos. Esta simulación usa dimensiones reducidas para hacerlo pedagógico.

MLA — Multi-head Latent Attention

El KV-cache en atención estándar crece con el número de tokens y ocupa gran memoria. MLA comprime las claves (K) y valores (V) a un espacio latente de menor dimensión (d_c = 4 en la simulación), y los reconstruye antes de calcular la atención. Esto reduce la memoria sin perder calidad.

MoE — Mixture of Experts

En lugar de procesar cada token con todos los parámetros, se disponen N expertos especializados. Un router selecciona los Top-K más relevantes para cada token. Un experto compartido siempre se activa. Esto permite escalar el modelo sin aumentar el cómputo proporcional.

Router y balance de carga

El router aplica función sigmoide (no softmax) sobre la proyección lineal del token, lo que permite que los scores sean independientes entre expertos. Un sesgo por experto ("expert bias") se ajusta durante el entrenamiento para evitar que siempre se elijan los mismos expertos.

Modo paso a paso

Permite detenerse en cada operación — tokenización, embedding, MLA, MoE, predicción — para observar los datos en cada etapa.

Modo automático

Avance continuo con velocidad configurable (0.8 s a 4 s por paso). Ideal para seguir el flujo completo sin interacción manual.

Hiperparámetros configurables

Podés cambiar la frase de entrada, la temperatura del Softmax, el número de expertos Top-K seleccionados y las capas a simular. Cada cambio reinicia la simulación para un nuevo recorrido.

¿Qué es un token?

Un token es la unidad mínima de texto que procesa el modelo. Puede ser una palabra completa, parte de ella, o un signo de puntuación.

En esta simulación, el vocabulario tiene solo 20 palabras del dominio IA (en castellano). En DeepSeek-V3 real el vocabulario es de 128 000 tokens.

Tokenización

El texto de entrada se divide en tokens y a cada uno se le asigna un ID numérico que lo identifica unívocamente en el vocabulario. Ese ID se usa para buscar su vector de embedding.

En modelos reales, palabras poco frecuentes se dividen en sub-tokens (subword tokenization). Por ejemplo, "tokenización" podría quedar como ["token", "ización"].

Vectores de Embedding

Cada token se mapea a un vector denso de d_model dimensiones (8 en la simulación; 7168 en DeepSeek real). Este vector es la representación semántica inicial del token.

embed(token) = W_embed[token_id] ∈ ℝ^d_model

Los pesos de la matriz de embedding W_embed se aprenden durante el entrenamiento. Tokens similares semánticamente terminan con vectores cercanos en el espacio.

El embedding es el punto de partida de toda la cadena de procesamiento. Las capas siguientes transforman estos vectores para capturar contexto.

Multi-head Latent Attention (MLA)

En la atención multi-cabezal estándar (MHA), el KV-cache crece con el número de tokens en contexto, ocupando mucha memoria. MLA lo comprime:

c = x · W_down ∈ ℝ^d_c   (d_c ≪ d_model)

Luego reconstruye K y V desde el vector latente c:

K = c · W_up_K   V = c · W_up_V

¿Por qué importa?

Al almacenar solo c (y no K, V completos), el KV-cache se reduce drasticamente. En DeepSeek-V3 la reducción es de ~13× respecto a MHA estándar.

Mixture of Experts (MoE)

En lugar de una sola FFN densa por capa, hay N expertos (redes FFN separadas), y un router elige cuáles activar por token:

  • Solo Top-K expertos se activan (K ≪ N)
  • Un experto compartido siempre contribuye
  • Los pesos del router se aprenden junto con los expertos

Ventaja principal

MoE permite tener modelos con muchos más parámetros (671 B en DeepSeek-V3) sin aumentar proporcionalmente el cómputo por token (solo 37 B activos).

El desafío es el balance de carga: que todos los expertos se usen de manera equitativa, no que solo unos pocos acaparen todo el tráfico.

¿Cómo funciona el router?

Para cada token, el router calcula un score por experto:

score_e = sigmoid(x · W_router[:,e] + bias_e)

La función sigmoide produce valores entre 0 y 1 de forma independiente por experto (a diferencia de softmax, que es competitivo).

Top-K y normalización

Se seleccionan los K expertos con mayor score. Sus pesos se normalizan (dividiendo por la suma) para que la combinación esté en la misma escala.

El "expert bias" (sesgo por experto) se ajusta durante el entrenamiento para forzar balance de carga: si un experto es muy usado, su bias baja.

Predicción del siguiente token

La representación del último token se proyecta al espacio del vocabulario mediante una capa lineal:

logits = x_last · W_out ∈ ℝ^|V|

Luego se aplica Softmax con temperatura para obtener probabilidades:

P(token) = softmax(logits / T)

Efecto de la temperatura

Temperatura < 1 → distribución más concentrada (más determinista). Temperatura > 1 → distribución más uniforme (más aleatoria / creativa).

En generación auto-regresiva, el token predicho se concatena a la entrada y el proceso se repite hasta generar el texto completo.
